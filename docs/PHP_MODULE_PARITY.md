| Security & governance (`security`) | Yes | Yes — 7 new tables | Yes | Yes | **Runtime validated.** All 17 endpoints ported: scorecard, self-test, prompt-guard scan, password strength, breaker list/reset, rate-limit tiers, events, encryption status, incidents (report/list/patch), access reviews (run/latest/attest) and incident runbooks (list/create). Node keeps incidents in one global Redis zset, breaker state in an in-process `Map` and events in a log ring; all three are MySQL here, and each was a bug in the original: incident lists and access reviews are now scoped to the caller's organization (one tenant could read another's incidents), `REVOKE_TOKENS` revokes the refresh tokens of the reporting organization instead of every session on the platform, and breaker state survives the request. Dormant-account detection derives last activity from the refresh-token ledger and the audit trail, because the PHP schema has no `lastLoginAt` column — an account that never logged in ages from its creation date rather than Node's `daysInactive: 9999` sentinel. The three self-tests Node hardcodes to `passed: true` (`headers.csp`, `csrf.middleware`, `rl.config`) now measure something: the header check reads back the headers actually emitted on the response (`nosniff` and `Referrer-Policy` always, HSTS on HTTPS only; CSP and framing are opt-in via `VP_SECURITY_CSP` / `VP_SECURITY_FRAME_ANCESTORS`, because the shipped SPA carries an inline boot script and the app is routinely embedded), the CSRF check compares `csrf_protection` against whether the app authenticates with browser-managed cookies (it does not — bearer tokens only, so CSRF is not applicable, and the check flips if cookie sessions are ever switched on), and the rate-limit check counts the 20 configured tiers while its detail states plainly that no server-side limiter is wired yet. Validated 153/153 parity plus 43/43 cPanel acceptance on both a fresh install and an install upgraded with migration `004_security_module.sql`; 28 web tests cover the new client functions, the event normaliser and the three governance tabs |
| Global Platform / observability + regions + CDN (`platform`) | Yes | Yes — 6 new tables | Yes | Yes | **Runtime validated.** All 15 endpoints ported: metrics, logs, traces, one trace, one span, AI observability, regions, the DR report, failover trigger/clear, CDN config, cache rules (PUT), purge and sign-url, and the combined overview. Node keeps all of this in process memory — metric Maps, a 2000-entry log ring, a 500-span ring, four module-level variables for failover, and two arrays for CDN rules and purges — so a faithful port would have reported zero spans, zero metrics and no failover state on every request. It is MySQL here: `platform_metric_counters` / `platform_metric_histograms` (one row per name/tag/minute, upserted, so a busy route costs one row a minute rather than one a request), `platform_spans`, `platform_state`, `platform_cdn_rules` and `platform_cdn_purges`. Every request opens a root span and records `http.request.count` + `http.request.duration_ms` under the same names Node's middleware uses, so the admin dashboard's panels find their series without a special case; W3C `traceparent` is honoured inbound and echoed outbound. Logs are **not** given their own table — the durable records this build keeps are `audit_events`, failed spans and failed AI requests, so `/platform/logs` merges those three and labels every row with its `source`, rather than inventing a ring buffer to look like Node's. Two numbers Node invents are reported as null: `replicationLagMs: 42` (a literal in `getDisasterRecoveryReport()` — a single-database deployment has no replica to measure) and `popCount: 42` / `cacheHitRate: 0.87` (labelled “simulated” in its own source) / `bandwidthGb: 12.4` (literals in `getCdnConfig()`). A purge with no provider configured is recorded as `skipped` with a reason instead of Node's 150 ms sleep followed by “complete”, and `sign-url` is a real HMAC-SHA256 over `VP_AUTH_SECRET` with `cdn_exp` then `cdn_sig`, so it is verifiable rather than decorative.
